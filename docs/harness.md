# 목표: 값싼 로컬 모델과 하네스로 복잡한 일을 해낸다

이 프로젝트가 어디로 가는지, 지금 어디에 있는지 적었다. 2026-10-22 에 썼다.

## 1. 목표

압력용기·판금 워크오더 하나(도면 여러 장)를 받아 판재 구매의뢰(POR)까지 만드는 일을, 로컬에서 돌아가는 작고 값싼 모델 여러 개로 해낸다. 성능은 큰 모델에서 나오지 않고 하네스에서 나오게 한다.

- **하네스**는 모델 바깥에서 모델이 일을 해내게 만드는 모든 것이다. 일을 어떻게 나누고, 단계마다 무엇을 보여 주고, 출력을 어떻게 제한하고, 계산을 누가 하고, 결과를 어떻게 검사하고, 틀리면 무엇을 하고, 무엇을 기록하고, 어떻게 평가하는지가 여기에 들어간다.
- **값싼 로컬 모델**은 이 레포의 GPU 서버(RTX A5000 24GB 두 장)에서 vLLM 같은 OpenAI 호환 서버로 띄울 수 있는 모델을 말한다.
- **복잡한 일**은 도면 1장의 형상 분류가 아니라 워크오더 전체다. 도면 세트를 읽고, 자재목록을 맞추고, 부품을 전개·분할하고, 판에 배치하고, 중량과 정답 커팅플랜으로 검증하는 데까지 간다.

## 2. 순서: Claude 로 시작해서 로컬로

처음부터 로컬 모델로 하면 결과가 나쁠 때 모델이 약해서인지 하네스가 잘못돼서인지 가를 수 없다. 그래서 순서를 둔다.

1. **Claude 로 일이 되는 하네스를 만든다.** v2 워크오더 에이전트([agent/skills.md](agent/skills.md))가 이 단계다. 일을 skill 단위로 나누고 절차를 정했다.
2. **같은 하네스에 Claude 를 꽂은 결과를 기준선으로 둔다.** 로컬 구성이 따라가야 할 상한이다.
3. **모델 자리를 로컬로 바꾸고, 차이를 하네스로 메운다.** 단계를 더 잘게 나누고, 검사와 재시도를 넣고, 모델에게 판단만 맡긴다. v3 도면 판독기([reader/framework.md](reader/framework.md))는 이미 OCR 모델과 추론 모델을 로컬 vLLM 으로 돌린다.
4. **조율까지 로컬 모델이 한다.** 다음에 어떤 단계를 부를지 고르는 일도 로컬 모델이 tool 호출로 한다.

Claude 의 자리는 셋이다. 하네스를 설계하고 고칠 때의 비교 대상, 기준선 측정, 그리고 코딩 에이전트로서의 개발 도구다. 최종 제품 경로는 조율까지 로컬 모델만 쓴다.

## 3. 원칙

- **모델은 판단하고, 계산은 코드가 한다.** 길이·각도·중량은 공식으로 계산한다. 이미 `reader/unfold.py` 가 이렇게 한다. 모델에게 전개 길이를 계산시키지 않는다.
- **일은 단계로 나누고, 단계는 파일로 입력과 출력을 주고받는다.** 단계 하나를 따로 돌리고, 결과를 사람이 보고 고치고, 거기서부터 다시 돌릴 수 있어야 한다 ([reader/stages.md](reader/stages.md)).
- **출력은 스키마로 제한하고 검증한다.** 작은 모델일수록 형식을 지키지 못한다. 서버의 제약 디코딩(vLLM xgrammar)과 코드 검증을 같이 쓴다.
- **단계마다 필요한 지식과 증거만 준다.** 지식 문서는 단계별로 고르고(`reader/knowledge.py` 의 `STAGE_TOPICS`), 무엇을 줬는지 sha256 으로 남긴다.
- **모든 모델 호출과 판단의 출처를 남긴다.** 값마다 `regex`, `vlm_reason:<모델>`, `overall_dimensions` 처럼 어디서 왔는지 적는다.
- **모델 호출은 OpenAI 호환 엔드포인트로 바꿀 수 있어야 한다.** 특정 회사 API 에만 있는 기능에 기대지 않는다.
- **평가는 단계별로 한다.** 전체 정답률만 보면 어느 단계를 고쳐야 하는지 모른다.
- **정답은 추론이 끝난 뒤에만 읽는다.** 지금 `batch.py` 가 이 순서를 지킨다.

## 4. 지금 상태 (2026-10-22)

하네스의 재료는 상당히 갖췄다. 하지만 하네스의 핵심인 "검사하고, 틀리면 고치는" 루프가 없고, 복잡한 일은 아직 로컬로 돈 적이 없다. 그래서 "값싼 로컬 모델과 하네스로 복잡한 일을 해낸다"는 말을 뒷받침할 근거는 아직 없다.

| 요소 | 상태 | 근거 |
|---|---|---|
| 일 나누기 | 있음 | v2: skill 25개, JSON 인자와 dict 결과 ([execution_flow.md](execution_flow.md) 2절). v3: 판독기 7단계, 2026-10-22 에 단계마다 따로 돌 수 있게 나눔 (`reader/stages/`) |
| 단계별 지식 | 있음 | `reader/knowledge.py` 의 `STAGE_TOPICS`, 쓴 문서의 sha256 을 trace 에 기록 |
| 출력 제한·검증 | 있음 | `reader/vlm_output.py` 의 응답 스키마와 검증, `experiments.sh` 의 xgrammar |
| 계산은 코드 | 있음 | 전개 `reader/unfold.develop`, 3D 복원 `reconstruct/`, v2 의 L3 |
| 검사 | 일부 | 표제란 척도와 도면 크기 대조, 최대 치수와 도면 크기 대조(`dxf_adapter.build_document`), 3D 후보 재투영 평가(`reconstruct/step4.py`), 위치 판단과 모델 판단의 불일치. v2 의 `verify_part_spec`, `verify_weight_vs_bom`, `verify_nesting`. 모델이 읽은 전개 파라미터를 도면 치수와 대조하는 검사는 없다 |
| 틀리면 고치기 | 없음 | 모델은 단계마다 한 번만 부른다. 실패하면 재시도 없이 결정적 폴백으로 간다(`reader/vlm.py` 의 `ask`). 검사 결과는 `review` 목록에 쌓이기만 하고 모델 재호출로 이어지지 않는다 |
| 기록 | 있음 | 단계 파일의 `trace`, 값마다 출처(`sources`). 전개·복원 단계 호출은 2026-10-22 부터 남는다 |
| 사람 확인 | 일부 | `review` 목록, v2 의 `ask_human`. 판단을 고쳐서 이어 돌리는 경로는 단계 분리로 생겼다 |
| 평가 | 일부 | 합성 도면 30장의 형상 분류 정확도(`accuracy.md`)와 전개도 1% 일치(`flat_patterns.md`). `label.json` 에 표제란·뷰·치수 정답이 있는데 단계별 채점에 쓰지 않는다. 실제 도면 평가 세트는 v3 에 없다 |
| 조율 | Claude 또는 고정 순서 | v2 는 Claude 가 조율한다(`agent/orchestrator.py`, Anthropic 전용 tool runner). v3 는 순서가 코드에 고정돼 있다(`stages/sequence.py`). 로컬 모델이 조율하는 경로는 없다 |
| 모델 고르기 | 역할 단위 | OCR·추론 두 역할만 바꿀 수 있다. 추론 모델 하나가 표제란, 뷰·형상, 전개 파라미터, 후보 확인을 모두 맡는다. 작업별로 다른 모델을 쓰거나 확신이 낮을 때 더 큰 모델로 넘기는 장치는 없다 |

지금 있는 숫자가 보여 주는 범위도 좁다. 동료의 27/30 은 로컬 모델(OCR DeepSeek-OCR-2 + 추론 Qwen3.6-27B)로 깨끗한 합성 DXF 30장의 형상을 분류한 결과다. 한 단계짜리 분류이고, 추론 모델은 bf16 가중치만 약 54GB 라 이 서버의 24GB GPU 두 장에는 그대로 올라가지 않는다. 워크오더 전체를 처리하는 v2 는 Claude 로만 돌고, 그마저 모델 경로는 기록상 실행된 적이 없다([agent/skills.md](agent/skills.md)).

## 5. 다음 단계

순서대로 한다. 각 단계는 결과를 숫자로 확인할 수 있게 만든다.

1. **단계 분리** — 판독기를 단계마다 따로 돌고, 보고, 고쳐서 다시 돌 수 있게 했다 (2026-10-22, 브랜치 `reader-stages`). 이미지 입력은 아직 한 단계로 묶여 있다.
2. **기록과 재생** — 단계 파일에 남은 모델 응답을 다시 틀어 주는 가짜 클라이언트를 만든다. GPU 없이 하네스 변경의 전후를 비교하는 회귀 테스트가 된다.
3. **단계별 평가** — `label.json` 으로 표제란 필드, 뷰 라벨, 투상법, 형상, 전개 파라미터를 단계마다 채점한다. 어느 단계가 틀리는지 보인다.
4. **작업별 모델 설정** — 단계(작업)마다 모델을 고를 수 있게 한다. 같은 평가로 모델 조합을 비교한다.
5. **검사 → 되먹임** — 검사가 실패하면 실패 내용을 넣어 다시 묻고, 몇 번 안에 안 되면 다른 모델이나 사람에게 넘긴다. 같은 질문을 여러 번 묻고 다수결을 내는 방법도 여기서 시험한다.
6. **로컬 조율자** — 단계 함수를 tool 로 노출하고, 로컬 모델이 OpenAI 호환 tool 호출로 단계를 고르고 부른다. 고정 순서와 결과를 비교한다.
7. **뒷단 연결** — 판독기 결과를 v2 의 전개·분할·네스팅·POR 로 넘겨 워크오더 전체를 로컬로 돌린다. 사람 커팅플랜(`gt/sheets.csv`)과 중량으로 평가한다.
8. **기준선 비교** — 같은 하네스에 Claude 를 꽂은 결과와 로컬 결과를 같은 평가 세트에서 비교한다.

목표 수치(예: 기준선의 몇 %)는 아직 정하지 않았다. 정하면 여기에 적는다.
